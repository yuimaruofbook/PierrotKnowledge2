## 1. インストール

必要なもの: [Bun](https://bun.sh)。

### Windows

```
SETUP.bat
```

依存関係の導入・ビルド・デスクトップショートカット作成・バンドルの雛形作成まで
一度に行います。

```
SETUP.bat -Connect
```

を使うと、続けて **エージェント側の設定ファイルへの追記**まで行います。

### macOS / Linux

```bash
bun install && bun run setup:unix
```

### 個別にビルドする

```bash
bun run build:view      # 画面（Web UI が配信するもの）
bun run build:headless  # エージェントが起動する MCP サーバー（単一実行ファイル）
bun run build:cli       # 単一実行ファイルの okf
```

> **ソースを変更したら、使っているモードに対応するものを再ビルドしてください。**
> Web UI は `build:view`、エージェント向けは `build:headless` です。
> `build:view` はヘッドレスのバイナリには影響しません（逆も同じ）。

## 2. 運用する 3 つのモード

**人間は Web UI、エージェントはヘッドレス、自動化は CLI。** この 3 つで運用します。

| モード | 誰が動かすか | 何を話すか | 常駐 |
|---|---|---|---|
| **Web UI** | 人間 | ブラウザ相手の RPC | **135 MB** |
| **ヘッドレス** | エージェント | stdio 越しの MCP | **85 MB** |
| **CLI** | どちらでも | 1 コマンド 1 応答 | — |

3 つは**別々のプロセス**で、調整役はいません。**同じフォルダのファイルで出会います。**
書き込み経路が 1 本しかないので、人間の編集とエージェントの編集が食い違いません。

### ブラウザで開く（人間の通常利用）

```bash
okf ui
```

`127.0.0.1` に立ち上がり、トークン付きの URL を表示してブラウザで開きます。
**常駐 135 MB**（サーバー 86 MB + タブ 49 MB）で、デスクトップ版の 633 MB に
対して約 5 分の 1 です。画面の中身は完全に同じものです。

- ネットワークには一切出しません（ループバック限定）
- ブラウザ内の他のページから操作されません（実行ごとのトークン）
- `Ctrl+C` で終了

> **「開く」**（`Ctrl+O`）を押すと、OS 標準のフォルダ選択ダイアログが出ます。
> ページがサーバーに頼み、サーバーが OS に頼む形です。デスクトップセッションが
> 無い環境（コンテナ、SSH 越し）では、パスの手入力に切り替わります。

### ヘッドレスで動かす（エージェントの運用形態）

**エージェントは必ずヘッドレスで動かします。** Claude Code / Codex / opencode /
Hermes が、次のバイナリを**自分で spawn** して stdio 越しに MCP で話します。

```bash
bun run build:headless   # build\headless\okf-mcp.exe を作る
```

- **画面を持たない 1 プロセス**です。これが 85 MB と 135 MB の差です
- **Bun のインストールも PATH も不要**な自己完結の実行ファイルです。
  エージェントホストがどんな環境から起動しても動きます
- 起動は接続パネルの **「すべてのエージェントに登録」** から行います。
  設定ファイルにこのバイナリのパスが書き込まれます

> **Web UI をエージェントに向けないでください。** あの画面が話すのはブラウザ相手の
> RPC であって MCP ではないため、エージェントから呼べるツールは 1 つもありません。
> 逆に、ヘッドレスは画面を配信しません。**両者はファイルで出会います。**

> **未ビルドだとフォールバックします。** バイナリが無い状態で登録すると、設定には
> `bun run …/standalone.ts` が書かれます。動きはしますが、エージェントホスト側の
> 環境に Bun が PATH にある場合だけです（GUI から起動されたホストでは無いことが
> あります）。`SETUP.bat -Connect` はこのバイナリを自動でビルドします。

> **ビルドは、エージェントが接続中だと失敗します。** 実行中の実行ファイルは
> Windows では置き換えられません。その旨を表示して中断するので、エージェント側の
> セッションを終了してから実行し直してください。**いま入っているバイナリは
> そのまま使い続けられます。**

### CLI で使う

```bash
.\PierrotKnowledge2 retrieve "検索したいこと"
.\PierrotKnowledge2 info
```

1 コマンド 1 応答で終了します。スクリプトから、あるいは画面を開いたまま
横で使う用途です。詳細は [okf CLI](cli.md)。

これで動いています。以降は必要になったところだけ読んでください。

## 3. バンドルの構造

```
bundle/
├── MAP.md     ← 層の外。どこに何があるか
├── human.md   ← 層の外。利用者について
├── Task.md    ← 層の外。未完了と直近の完了
├── raw/       第 1 層: 入ってきた原本
├── wiki/      第 2 層: 正典
└── .rag/      第 3 層: 検索索引（自動生成・手で触らない）
```

**層は 3 つだけです。** 上の 3 ファイルは層の外に置いています。
3 層は同じ素材の 3 段階（原本 → 正典 → 派生）ですが、この 3 つはその素材では
ないからです。置き場所の説明・人・進行中の作業であって、知識ではありません。

| | `raw/` | `wiki/` | `.rag/` |
|---|---|---|---|
| 人間 | ○ | ○ | アプリ経由 |
| エージェント | **×** | ○ | アプリ経由 |

`raw/` はあなたの受信箱です。Notion や Google ドライブからの取り込みもここに
入ります。**エージェントは書けません** — 要約する側が、実際に届いた記録を
書き換えられないようにするためです。

`wiki/` の中は人間もエージェントも自由に作成・編集・移動できます。
`raw/` から `wiki/` へ引き上げるのは人間の操作です。

### `wiki/` の中身

```
wiki/
├── AGENTS.md      エージェント向けの規約（全文）
├── 1-projects/    PARA: 進行中（終わりがある）
├── 2-areas/       PARA: 期日はないが優先したい関心
├── 3-resources/   PARA: 役立つ知識（既定）
├── 4-archive/     PARA: 現在使っていない
├── skills/        <カテゴリ>/<スキル名>/SKILL.md
├── loops/         繰り返す作業の設計。1 設計 = 1 ファイル
├── index.md       OKF §8 予約
└── log.md         OKF §9 予約
```

`AGENTS.md` と `skills/` `loops/` は**層ではなく wiki の中身**です
（いずれも「ウィキについて」の内容だからです）。
いずれも知識としては索引されないので、タスク一覧や個人情報が
事実の検索結果に混ざることはありません。

## 4. 画面の構成

```
┌──────────────────────────────────────────────┐
│ PierrotKnowledge2  [開く][新規][保存][再構築][接続][Skill] │ ツールバー
├──────────────────────────────────────────────┤
│ [表示|編集]  H1 H2 H3 B I S <> " 〜 ≡  [幅 ──●] │ 書式バー
├────────────┬─────────────────────────────────┤
│ ファイル   │                                  │
│ ツリー     │      本文（表示 / 編集）          │
│            │                                  │
│ タグ       │      バックリンク                 │
├────────────┴─────────────────────────────────┤
│ ステータス                                    │
└──────────────────────────────────────────────┘
```

**中央は 1 面です。** エディタとプレビューを左右に分けず、同じ場所を
切り替えます。

## 5. ノートを読む・書く

### 開くとまずプレビュー

`.md` を開くと**表示（プレビュー）で始まります**。読みに来たページで
frontmatter やリンク記法が最初に目に入るのは違うためです。

書式バー左の **[表示 | 編集]** で切り替えます。バイナリと Markdown 以外の
テキストは、描画するものが無いので最初から編集で開きます。

### 書式バー

| ボタン | 内容 |
|---|---|
| H1 / H2 / H3 / P | 見出しと段落 |
| **B** / *I* / ~~S~~ | 太字・斜体・打ち消し |
| `<>` | インラインコード |
| 箇条書き / 番号 / チェック | リスト 3 種 |
| `"` | 引用 |
| 🔗 | リンク |
| ≡ | 左寄せ・中央・右寄せ |
| ─ | 水平線 |
| ⊞ | 表 |

**すべてトグルです。** 見出しにもう一度 H2 を押すと段落に戻ります。

### 幅スライダー

本文の横幅を変えられます。既定は全幅。動かすとその場で反映され、
手を離した時点で保存されます。

### 保存

`Ctrl+S`。加えて**自動保存**が入っているので、通常は意識不要です。

### 貼り付け

他のツールからのコピーは**書式を保ったまま**入ります。HTML を
Markdown に変換してから挿入するので、見出しや箇条書きが平文に
潰れません。

## 6. リンクとバックリンク

### 書き方

```markdown
[[概念名]]              ウィキリンク
[[概念名|表示テキスト]]  表示だけ変える
[通常のリンク](path.md)  標準 Markdown
```

`[[` を打つと候補が出ます。

### 未解決リンク

存在しないページへのリンクは色が変わります。クリックすると
**その場で作成**できます。

一覧は `Ctrl+Shift+P` →「未解決リンク」、または `okf gaps`。

### バックリンク

本文の下に「このページを参照しているページ」が自動で並びます。

## 7. PARA で優先度をつける

`wiki/` の直下は 4 つに分かれています。

| フォルダ | 意味 |
|---|---|
| `1-projects/` | 進行中。終わりがある |
| `2-areas/` | 期日はないが優先したい関心 |
| `3-resources/` | 役立つ知識（既定） |
| `4-archive/` | 現在使っていない |

**この順序は検索順位に効きます。** 同じ内容でも `1-projects/` にある方が
上に出ます。`4-archive/` は順位が大きく下がり、スキル選択からは
完全に除外されます。

移動はツリーのドラッグ、または:

```bash
okf archive wiki/1-projects/終わった件.md archive
```

## 8. 検索

### 全文検索

ツールバーの検索欄（`Ctrl+K`）。BM25 で順位づけし、一致箇所を
ハイライトします。

**日本語はバイグラム索引**なので、単語の区切りが無くても一致します。
「設計原則」で「〜の設計原則を〜」が引っかかります。

### クイックスイッチャー

`Ctrl+P`。ファイル名の曖昧一致で飛びます。

### タグ

frontmatter の `tags` は左下に一覧されます。クリックで絞り込み。

## 9. ファイル操作

ツリーの右クリックから、新規・改名・移動・削除。

**改名すると、そのページを指すリンクが全部書き換わります。** 手で直す
必要はありません。移動も同じです。

## 10. ショートカット

| キー | 動作 |
|---|---|
| `Ctrl+S` | 保存 |
| `Ctrl+P` | クイックスイッチャー |
| `Ctrl+Shift+P` | コマンドパレット |
| `Ctrl+K` / `Ctrl+F` | 検索 |
| `Ctrl+O` | バンドルを開く |

編集中は、リストや引用の途中で `Enter` を押すと**次の行も同じ記法で
続きます**。空の項目で `Enter` を押すとリストを抜けます。

## 11. 接続パネル

ツールバーの **「接続」**。**1 ページに 3 セクション**が縦に並びます。

### 外部サービス (MCP)

Notion・GitHub・Google ドライブ・**Obsidian** など。行をクリックすると、
その場で詳細（接続 / ツール選択 / 引数 / 取り込み）が開きます。

1. 下の **＋ Notion** などで定義を追加
2. **「設定ファイルの場所」**でパスを表示し、そのファイルにトークンを書く
3. **「接続」**

> **トークンをこのアプリに入力することはありません。** 設定ファイルの
> 場所を示すだけで、値はアプリを通りません。

取り込んだ内容は **`raw/` にのみ**保存されます。`wiki/` には自動で
入りません。

#### Obsidian から移行する

**＋ Obsidian** で追加してから、設定ファイルの `<VAULT_PATH>` を Vault
フォルダの**絶対パス**に書き換えてください。

```json
"args": ["-y", "mcp-obsidian", "C:/Users/you/Documents/MyVault"]
```

書き換えないまま「接続」を押すとフォルダが無いと言われるので、パネル側でも
警告を出します。

> **Vault は変更されません。** 使うのは読み取り専用の `mcp-obsidian` です。
> 書き込みもできる `obsidian-mcp` という別実装もありますが、そちらは README の
> 冒頭で「使う前に Vault をバックアップしてください」と断っています。
> 取り出すだけなら書き込みは不要なので、Vault に触れない方を既定にしています。

接続後は他のサービスと同じで、ツールを選んで取り込むと **`raw/` に入ります**。
Obsidian のノートは元々 Markdown なので、そのまま `wiki/` へ引き上げられます。
`[[ウィキリンク]]` の記法も共通です。

### エージェント接続

**「変更内容を見る」**で書き込む全文を確認してから、**「ワンタッチ接続」**。
上書き前に必ず `<ファイル>.okf-backup-<時刻>` に退避し、**既存の設定は
消しません**（1 エントリの追加・置換のみ）。

#### バンドル限定（プロジェクトスコープ）

そのバンドルを開いたときだけ有効です。**あなたの全体設定に一切触れません。**

| ツール | 設定ファイル |
|---|---|
| Claude Code | `<バンドル>/.mcp.json` |
| Cursor | `<バンドル>/.cursor/mcp.json` |
| Antigravity CLI | `<バンドル>/.agents/mcp_config.json` |

#### 全プロジェクト（ユーザースコープ）

どのフォルダで起動しても有効です。

| ツール | 設定ファイル |
|---|---|
| Codex | `~/.codex/config.toml` |
| opencode | `~/.config/opencode/opencode.json` |
| Hermes Agent | `~/.hermes/config.yaml` |
| Antigravity | `~/.gemini/config/mcp_config.json`（IDE / CLI 共通） |
| Cursor（全プロジェクト） | `~/.cursor/mcp.json` |
| Claude Code（全プロジェクト） | `~/.claude.json` — **コマンドを表示します** |

最後の 1 つだけ、**本アプリは設定ファイルを書きません。** Claude Code の
ユーザースコープは `~/.claude.json` に入りますが、このファイルはプロジェクト
状態やサーバーの有効/無効も持っています。1 エントリのために書き換えると動いて
いる環境を壊しかねないので、公式が案内する `claude mcp add` のコマンドを
表示します。そのままコピーして実行してください。

#### 一覧に無いツールに繋ぐ

同じ PC の MCP 対応ツールは、上の 9 つだけではありません。**一覧に無いツールへは、
設定を出力して貼り付けます。**

```powershell
.\PierrotKnowledge2 mcp-config                    # ほとんどのホスト（mcpServers 形式）
.\PierrotKnowledge2 mcp-config --format toml      # Codex 系（TOML）
.\PierrotKnowledge2 mcp-config --format opencode  # opencode 系
.\PierrotKnowledge2 mcp-config --format yaml      # YAML を取るホスト
.\PierrotKnowledge2 mcp-config --format command   # コマンド 1 行だけ欲しいとき
```

出力例:

```json
{
  "mcpServers": {
    "okf-wiki": {
      "command": "C:/…/build/headless/okf-mcp.exe",
      "args": [],
      "env": { "OKF_BUNDLE": "C:/…/OKF Wiki" }
    }
  }
}
```

**ワンタッチ接続と同じサーバーを指します。** どちらも `serverSpecFor` から
組み立てているので、貼った設定と書かれた設定が食い違うことはありません。
ヘッドレスが未ビルドなら `bun run` 形式になり、その旨を注意として表示します。

**書き込むのではなく表示するのは意図的です。** 形式を検証していないツールの
設定ファイルを書き換えると、Hermes で実際に起きたように「書けたのに繋がって
いない」状態を作りかねません。貼る先はあなたが選んでください。

#### Orca など、作業ディレクトリが変わる環境

[Orca](https://github.com/stablyai/orca) 自体に MCP 設定はありません。Orca は
Codex / Claude Code / opencode / Pi を**それぞれ別の git worktree で並列に
動かす**オーケストレータなので、繋ぐ相手は配下のエージェントです。

このとき**作業ディレクトリがバンドルになりません。** つまり上の
「バンドル限定」は見つけてもらえないので、**「全プロジェクト」を選んでください。**

### ローカル実行

Ollama・llama.cpp・**LM Studio**・**vLLM** は **MCP クライアントではありません**。
ツール呼び出しを出力できても実行する側がないので、**本アプリがエージェント
ループを内蔵**しています。

| サーバー | 既定のエンドポイント | 注意 |
|---|---|---|
| Ollama | `localhost:11434/v1` | tools 対応モデルが必要 |
| llama.cpp | `localhost:8080/v1` | `--jinja` 必須 |
| LM Studio | `localhost:1234/v1` | モデルを読み込み「Start Server」 |
| vLLM | `localhost:8000/v1` | `--enable-auto-tool-choice` と `--tool-call-parser` の**両方**が必要 |

いずれも認証は不要です（ループバック限定のため）。

サーバー・モデル・依頼を選んで実行すると、各ステップと**消費トークンが
その場で流れます**。

## 12. デイリーノート

その日の書き留め場所です。会議、決めたこと、あとでやること —— どこに置くかを
先に決めずに、まず書くための場所です。

### 開く

| 経路 | 操作 |
|------|------|
| UI | `Ctrl+Shift+P` →「今日のノート」 |
| CLI | `okf today` |

**既にあれば開くだけ、無ければ作成**です。どちらでも 1 アクションで、
「今日の分はもうあったか」を確かめる必要はありません。

作られる場所は `wiki/daily/2026-08-03.md` です。日付はローカル日付で採ります。

### 雛形

```markdown
## タスク

- [ ]

## メモ

## 今日わかったこと
```

空白のページではなく見出しを入れてあります。白紙だとその日ごとに違う形になり、
翌週には見比べられなくなるためです。

### 普通のページとして扱われます

`skills/` や `loops/` と違い、**検索の対象になります**。
「先週の火曜に何を決めたか」は実際に起きる質問で、索引に入っていなければ
答えられません。リンクもバックリンクも普通に効きます。

### タスクは Task.md に移る（エージェント規則）

`## タスク` の下に**未チェック**の項目を書いておくと、エージェントが
`collect_daily_tasks` で `Task.md` に移します。

```markdown
## タスク

- [ ] 議事録を wiki に取り込む     ← 移動の対象
- [x] 資料を集める → T-0011        ← 済み。二度と移動しない
```

移動後、ノート側の行は `[x]` と付与された ID に書き換わります。

**なぜ移すのか:** その日のノートに書いた要件は、翌日には誰も見ません。
実際に読まれるのは `Task.md` です。書く場所と読まれる場所が違うので、
移し替えないと要件は消えます。

**巻き込みません:**

- 対象は `## タスク` の下**だけ**です。メモ欄に書いた持ち物リストや
  手順の確認は移動しません
- **二重登録されません。** チェック済みは対象外なので、何度呼んでも増えません
- 移ったタスクには「YYYY-MM-DD のノートから」と出所が入ります

手で `okf collect-daily-tasks` を叩いても同じことが起きます。

## 13. 更新とアンインストール

どちらも **`PierrotKnowledge2`** コマンドです。`okf` でも動きますが、短い
一般語で他のツールと衝突しうるため、アプリ名のほうを使ってください。

> **アプリのフォルダで、先頭に `.\` を付けて実行してください。**
> セットアップは PATH を書き換えないので、PowerShell では `.\` が無いと
> `CommandNotFoundException` になります（PowerShell はカレントディレクトリの
> プログラムを既定では実行しません）。macOS / Linux では `./` です。
> 前置きなしで打ちたい場合は、ご自身で PATH に追加してください。

### 更新

```powershell
.\PierrotKnowledge2 Update           確認のみ。検証して内容と判定を表示
.\PierrotKnowledge2 Update --apply   実際に適用する
```

新しい版があってオンラインなら、**ツールバーに「アップデート」が現れます**
（緑の点が明滅します）。押すとリリースノートが読めます。

- ダウンロードは **GitHub が計算した sha256 と照合**します
- **古い版へは戻しません**（バージョンが下がる更新は拒否）
- 旧ファイルは削除せず退避。`--rollback <退避先>` で戻せます
- **バンドルがアプリのフォルダ内にある場合は更新自体を拒否します**

### アンインストール

```powershell
.\PierrotKnowledge2 Uninstall           計画を表示（何も消さない）
.\PierrotKnowledge2 Uninstall --apply   実行
```

**「残るもの」を先に表示します。** アンインストールで本当に知りたいのは
そこだからです。

```
残るもの（削除しません）:
  ✅ C:\Users\you\Documents\OKF Wiki
  ✅ …\PierrotKnowledge2\session.json

削除・変更するもの:
  編集  Claude Code の設定から MCP エントリを削除
  削除  ランチャー / ショートカット
```

**ノートは消しません。** アプリのフォルダ内にバンドルがある場合は、全体を
中止します。

代わりに行うのは手作業では面倒な部分です。**各エージェントの設定から MCP
エントリを抜きます。** 放置すると Claude Code も Codex も Cursor も、起動の
たびに「存在しないプログラムのサーバーが壊れている」と報告し続けます。
編集前に必ず退避します。

設定（セッション・接続先の登録）は `--purge-settings` を付けたときだけ
消します。

> **アプリのフォルダ自体は削除しません。** 実行中のプログラムは自分自身を
> 消せないためです。アプリを終了してから手で削除してください。

## 14. SkillSpace

ツールバーの **「Skill」**。手順書の置き場です。

エージェントは常時**名前と説明だけ**を読み、必要と判断したものだけ本文を
開きます。実測で**トークン 58% 削減**。

入力欄に依頼文を入れると、**どのスキルが選ばれ、開くと何トークンかかるか**を
その場で試せます。試すこと自体はトークンを消費しません。

構造は `skills/<カテゴリ>/<スキル名>/SKILL.md` です。

詳細 → [SkillSpace](./skillspace.md)

## 15. MAP・human・Task

バンドル直下、**3 層の外**にある 3 つの案内ファイルです。

| ファイル | 中身 | CLI |
|---|---|---|
| `MAP.md` | どこに何があるかの経路表 | `okf map` |
| `human.md` | あなたのこと（呼び方・進め方・制約） | `okf who` |
| `Task.md` | 未完了と直近の完了 | `okf tasks` |

**`MAP.md` は最初に読まれます。** 実測で MAP は 522 トークン、案内 4 ファイル
全部だと 2342 トークン。MAP を見て必要な 1 ファイルだけ開けば、全部読むのに
比べて約 3 割で済みます。

`MAP.md` の上半分は自動生成です（実装とズレないため）。区切り線より下は
自由記述で、再生成しても保持されます。

`human.md` は雛形が入っているだけなので、**中身はご自身で埋めてください。**
毎回読まれるので短く保つのが得です。

`Task.md` は手で編集して構いません。**状態は見出しで決まります**
（`## 進行中` / `## 未着手` / `## 完了`）。チェックボックスではありません。
完了は直近 25 件まで残り、それ以前は件数だけ保持します。

## 16. コマンドライン

```bash
okf ask "LLM wiki とは"        出典付きで答える
okf search "設計原則" --limit 5
okf map / okf who / okf tasks
okf todo "資料をまとめる" --para project
okf lint                       OKF 準拠チェック
okf gaps                       未解決リンク
okf serve                      MCP サーバーとして起動
```

対象バンドルは `--bundle` → 環境変数 `OKF_BUNDLE` → 前回アプリで開いたもの、
の順です。最後のフォールバックがあるので、ウィンドウを開いたまま横で叩けます。

長い作業は RMUX セッションに預けられます（`okf rmux setup` → `run` →
`capture`）。詳細 → [okf CLI](./cli.md)

## 18. 困ったとき

| 症状 | 対処 |
|---|---|
| **セットアップが途中で失敗する** | v0.4.1 以降は「どの処理が」「終了コード幾つで」失敗し、手で再実行するコマンドまで表示されます。その全文を添えて報告してください |
| バンドルのフォルダを作れない | Documents が使えない場合はユーザーフォルダなどへ自動で切り替えます（切り替えた旨を表示します）。それでも失敗する場合は `SETUP.bat -BundlePath "C:\okf-wiki"` で別の場所を指定してください |
| `Could not find a part of the path '...\.okf-write-test'` | `Documents` が `Test-Path` では存在するのに実際には使えない状態です。原因は 4 通りあり、セットアップがどれかを判定して表示します。詳細は [Documents フォルダが使えないとき](#documents-フォルダが使えないとき) |
| `-BundlePath` が効かない | **パスの末尾に `\` を付けないでください。** 閉じ引用符が打ち消され、後続のオプションごとパスに飲み込まれます |
| **変更したのに画面が変わらない** | `bun run build:view` を実行してページを再読込。`ui` は `src/mainview/dist` の中身を配信します |
| **変更したのにエージェント側の挙動が古い** | `bun run build:headless` を実行し、エージェントのセッションを開き直してください。古いバイナリを spawn したままです |
| `ui` が起動しない | 前回のサーバーがポートを掴んでいることがあります。前のコンソールを `Ctrl+C` するか `--port` を指定してください |
| 文字化けする | 保存し直してください。読み書きは UTF-8 固定です |
| 検索が古い | ツールバーの「再構築」 |
| 日本語が検索に出ない | 同上。バイグラム索引の再構築が要ります |
| エージェントが `raw/` に書けない | **仕様です。** 人間が `wiki/` へ引き上げてください |
| 接続でエラーが赤枠で出る | トークン未設定が最多。本文はサーバーの出力そのままです |
| `rmux` が動かない | 事前ビルド版が壊れています。`cargo install rmux --locked` |

### デスクトップアイコンが開くもの

アイコンをダブルクリックすると 127.0.0.1 にサーバーが立ち、既定のブラウザで開きます。
小さな黒いウィンドウが最小化された状態で残り、**それを閉じると終了**します
（サーバーの実体なので、閉じるまで動き続けます）。

ウィンドウ版は 0.5.0 で廃止しました。同じ画面で常駐 633 MB（タブなら 135 MB）、
固有機能はフォルダ選択ダイアログだけで、それは OS に直接開かせる方式に置き換えました。

アイコンにはセットアップ時のバンドルの場所が埋め込まれます。別のバンドルに向けたい場合は
`.\SETUP.bat -BundlePath "C:\別の場所"` で作り直してください。

### Documents フォルダが使えないとき

`Could not find a part of the path '...\.okf-write-test'` は、`Documents` が
**存在するように見えて実際には使えない**ときに出ます。`Test-Path` は `True` を返し、
`New-Item -Force` は成功したと報告して何も作らないため、最初に正直なエラーが出るのが
書き込みの瞬間になります。原因は次の 4 つで、いずれもクラウド同期とは限りません。

| 状態 | 典型的な経緯 |
|---|---|
| `Documents` がリンクで、リンク先が消えた | 別ドライブへ移動した後にその場所を削除／リネームした。外付けドライブを外した。クラウド同期（OneDrive / Dropbox / Google Drive など）のフォルダ移動を解除した |
| `Documents` がリンクで、リンク先がファイルになった | 同上＋リンク先の場所に同名ファイルが作られた |
| `Documents` がフォルダではなくファイル | 同名ファイルを作ってしまった／展開ミス |
| `Documents\PierrotKnowledge2` が既にファイル | 同名ファイルが場所を塞いでいる |

セットアップはこの 4 つを判定して該当する対処を表示し、**Documents が駄目でも
ユーザーフォルダなどへ自動で切り替えて続行します。** 手元で状態を確認したい場合:

```powershell
$p=[Environment]::GetFolderPath('MyDocuments'); $c=Join-Path $p 'PierrotKnowledge2'
foreach($x in @($p,$c)){
  $i=Get-Item -LiteralPath $x -Force -EA SilentlyContinue
  if(-not $i){ "$x : MISSING"; continue }
  $o='OK'; try{ Get-ChildItem -LiteralPath $x -Force -EA Stop | Select-Object -First 1 | Out-Null }
  catch{ $o="FAIL($($_.Exception.GetType().Name))" }
  "$x`n  attrs=$($i.Attributes) link=$($i.LinkType) target=$($i.Target) open=$o"
}
```

`attrs` に `ReparsePoint` があればリンク、`Directory` が無ければファイルです。
`open=FAIL` が出た行がそのまま原因の場所です。
