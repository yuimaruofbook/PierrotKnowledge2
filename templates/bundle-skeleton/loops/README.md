# loops/ — ループ設計と実行履歴

「ループ」は**繰り返し使う作業の型**です。例:

- 議事録を取り込む
- 週次で健全性を点検する
- 出典付きで質問に答える

## 原則: 1 つのループ設計 = 1 ファイル

```
loops/
├── ingest-notes.md    ← 議事録取り込みループ（設計 + 実行履歴）
├── weekly-lint.md     ← 週次点検ループ（設計 + 実行履歴）
└── README.md
```

**実行するたびにファイルは増えません。** 同じ設計を 100 回実行しても
ファイルは 1 つで、その中に履歴が積み上がります。

実行ごとにファイルを作る方式だと、同じ作業の記録が何百件にもなり、容量も
可読性も破綻します。設計単位なら「この作業、前回はどうだったか」を
1 ファイル見るだけで分かります。

この原則は運用ルールではなく**強制**されています。

- 別々の設計が同じファイルを共有することはありません。
- 同時に実行できるループは 1 つだけです。実行中に別のループを始めようとすると
  拒否されます。
- 設計を編集しても、過去の実行履歴は書き換わりません。

## ファイルの中身

```markdown
---
loop: weekly-lint
goal: 週次で知識ベースの健全性を点検する
skill: wiki-lint
runs: 12
status: idle
---

## 設計
- 使うスキル、完了条件

## 実行履歴
### 2026-08-02T09:00:00Z — done
- 開始: 概念 42 / 非準拠 0 / 未解決 7
- 終了: 概念 45 / 非準拠 0 / 未解決 9 (概念 +3 · 非準拠 ±0)
- 経過: 何をしたか
- 結果: 何を達成したか
```

## 履歴の上限

ファイルが際限なく育たないよう、履歴には上限があります。

| 範囲 | 残るもの |
|------|---------|
| 直近 5 回 | 経過を含む全記録 |
| それ以前（25 回まで） | 1 行の要約 |
| さらに古いもの | 件数のみ |

読めなくなった記録は記録ではないため、古いものから畳まれます。
累計実行回数は frontmatter の `runs` に残ります。

## このディレクトリの位置づけ

知識ではなく**作業の型と記録**です。そのため:

- 検索 (`search` / `retrieve`) の対象外です — 手順や作業ログが事実と同じ
  検索結果に混ざると、知識ベースとして使えなくなります
- OKF の概念ドキュメントではないので、frontmatter の `type` は不要です
- 不要になった設計は削除して構いません
