# 知識ベースを手入れする

LLM Wiki パターンでいう **lint** です。取り込みを続けると必ず劣化するので、
定期的に回してください。

## 手順

### 1. OKF 準拠

`check_conformance` を実行します。よくある違反は次の 3 つです。

| 違反 | 直し方 |
|------|-------|
| frontmatter が無い | `type` を追加する。最低限それだけでよい |
| `type` が空 | 内容に合う型を入れる |
| 予約ファイルに frontmatter | `index.md` / `log.md` からは frontmatter を削除する |

**書きかけを理由に拒否しないでください。** OKF §11 は、任意項目が無いことを
理由に文書を拒否してはならないと定めています。直すのは `type` の欠落だけです。

### 2. 未解決リンク

`unresolved_links` を実行します。**全部を埋めようとしないでください。**

- **2 回以上参照されている** → 書く価値があります
- **1 回だけ、かつ古い** → 書くのではなく、リンクを外すことを検討する

未解決リンクは計画です。埋めることではなく、**計画として正しい状態に保つこと**が目的です。

### 3. 重複

`list_concepts` で一覧を出し、似たタイトルを探します。見つけたら:

1. 両方を `read_file` で読む
2. どちらが正本かを決める
3. もう一方の内容を統合する
4. 削除する側から正本へリンクを張る（履歴が切れないように）

**勝手に削除しないでください。** 統合してリンクを残すのが正しい後始末です。

### 4. 索引

`rebuild_index` と `rebuild_rag` を実行します。
`.rag/` は派生物なので、壊れていても再構築すれば直ります。

## やらないこと

- 全ページを機械的に書き換える（差分が読めなくなります）
- 未解決リンクを一括で埋める（薄いページが量産されます）
- 型を統一するためだけに型を変える（検索性が上がらないなら意味がありません）
