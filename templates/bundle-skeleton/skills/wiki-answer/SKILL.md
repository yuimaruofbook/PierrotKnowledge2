# 知識ベースから答える

## いちばん大事なこと

**`search` ではなく `retrieve` を使ってください。**

- `search` は**ページを探す**ためのもの。1 ページにつき 1 件返します。
- `retrieve` は**答えるため**のもの。見出し単位の本文を、引用アンカー付きで、
  文字数予算内にまとめて返します。

質問に答えるのに `search` を使うと、ページ名だけ見て中身を推測することになります。

## 手順

1. `retrieve` に**ユーザーの質問文をそのまま**渡す。
   キーワードに分解しないでください — 日本語は前後の文脈込みで索引されています。
2. 返ってきた各パッセージの `source` と `anchor` を確認する。
3. 足りなければ `budget_chars` を増やすか、`expand_neighbours: true` で
   前後の節も取る。
4. 答えを書く。**各主張に出典を付ける。**

## 出典の付け方

`retrieve` が返す `anchor`（例: `design.md#最高軽量`）は実在のファイル位置です。
人間が開いて検証できます。この形で残してください。

> ノートの正本はローカルの Markdown です。
> （出典: `wiki/design.md#file-over-app`）

## 知識ベースに無いとき

**推測で埋めないでください。** 「この知識ベースには記載がありません」と言うのが
正しい答えです。そのうえで:

- `unresolved_links` を見る。誰かが既に「書くべき」と印を付けているかもしれません。
- ユーザーに、いま答えた内容をページ化するか尋ねる。

知識ベースの価値は「書いてあることは正しい」という信頼です。
埋め合わせの推測はその信頼を壊します。

## 絞り込み

- 特定の分野だけ見たい: `tags: ["design"]`
- 決定事項だけ見たい: `type: "Decision"`
- 特定フォルダだけ: `path_prefix: "wiki/projects/"`
